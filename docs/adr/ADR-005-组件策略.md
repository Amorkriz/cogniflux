# ADR-005 组件策略：自建 + CVA + 选择性 shadcn/Radix

- 状态：已采纳（2026-07）
- 相关：基线 §10、[ADR-004](./ADR-004-设计令牌.md)

## 背景

完整组件库（MUI 等）带来强烈模板感，与"有辨识度"的定位冲突；完全自建则无障碍逻辑（焦点/键盘/ARIA）成本高。

## 决策

- 简单基础组件**自建**（Button/Card/Badge/Tag/Input/Skeleton/EmptyState/Separator），变体经 **CVA** 声明式管理，`cn()`（clsx + tailwind-merge）合并类名。
- 复杂交互组件走 **shadcn/ui 模式**（复制源码/基于 Radix 原语进仓库）：当前落地 Dialog/Tabs/Tooltip（`@radix-ui/react-dialog/tabs/tooltip`），**默认样式必须重刷为自己的令牌**，避免"shadcn 脸"。
- 四层归属：`shared/ui`（零业务）→ `shared/components`（≥2 领域复用）→ `domains/x/components`（props 含领域类型）→ `pages/*`（页面内组合，不导出）。
- 图标统一 lucide-react，只从 `shared/ui/icon` 出口导入（未来换库只改一处）。
- Storybook 不引入，用 `/dev/ui` 内部路由页陈列组件。

## 理由

- Radix 提供生产级键盘/焦点/ARIA 行为，源码在自己仓库，无运行时锁定、无迁移问题。
- CVA 把"变体 → className 组合"收敛为声明，防 className 失控。
- 四层归属判据明确（"换个网站还能用吗？几个领域在用？props 有领域类型吗？"），防三大桶失控。

## 后果

- 抽取纪律："两次规则"——第 2 次复用才上移一层，禁止预防性抽象。
- 防万能组件：props >8 或出现 `type/mode` 开关分叉渲染必须拆分。
- 无障碍清单：Tab 可达、焦点环（`--color-focus-ring`）、`<button>` 语义、alt 必填、触控 ≥44px。
- 规范：文件 PascalCase、一律具名导出、Props 类型 `XxxProps` 导出、每层 `index.ts` 公开边界。

## 重新评估条件

需要 CommandPalette/DropdownMenu 等新复杂组件时按同一模式引入 Radix 原语；组件消费方 ≥2 个应用时评估抽 `packages/ui`（见 ADR-007）；阶段 2 视需要重估 Storybook。
