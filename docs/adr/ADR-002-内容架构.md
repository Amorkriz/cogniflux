# ADR-002 内容架构：MDX + TS 数据 + 根目录 content/

- 状态：已采纳（2026-07）
- 相关：基线 §7/§8、[ADR-003](./ADR-003-内容访问抽象.md)、docs/CONTENT.md

## 背景

内容是长期资产，需选定主格式与组织方式。备选：全 Markdown、YAML/JSON 主数据、第一阶段接 Headless CMS。

## 决策

- 长文（Article/Lab）用 **MDX**：`content/articles/{年}/{slug}/index.mdx`（图片同目录）、`content/lab/{slug}.mdx`。
- 结构化数据（Project/Agent/Tool/Now/Profile/Site）用 **TS 数据文件**：`content/data/*.ts`。
- 内容统一放**根目录 `content/`**（独立于 src），`_templates/` 提供各类型 frontmatter 模板。
- 全部 frontmatter 经 Zod 构建期校验（`pnpm validate-content` + vite buildStart 插件双入口），失败即构建失败。

## 理由

- MDX 支持文中嵌 React 组件（未来嵌交互 Demo），纯 Markdown 做不到。
- TS 数据文件天然获得类型检查与 IDE 补全，比 YAML/JSON 少一层校验（YAML 仅用于 frontmatter）。
- 单人写作期 Git + MDX + 模板已是最优编辑体验；此时接 CMS 是最典型的过度设计。

## 后果

- slug 纪律：手写、小写连字符、不含日期、发布后不改（改则 301 + 别名表）；文章 slug 须与目录名一致。
- 草稿：`status: draft` dev 可见（DRAFT 角标），生产构建过滤。
- prerender/sitemap 的路径枚举经 `scripts/content-urls.ts`（fs + gray-matter），因 RR 加载 config 的环境无项目 alias——与领域层同一套 published 过滤规则。
- 三级组织（类型/年份/slug）+ 模板 + CI 校验防"内容大杂烩"。

## 重新评估条件

内容 >50 篇或出现多人编辑/网页端写作需求时评估 CMS（首选 Keystatic，Git-based、内容仍是 MDX 文件、几乎零迁移）。
