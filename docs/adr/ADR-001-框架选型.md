# ADR-001 框架选型：React Router v7/v8 + Vite prerender 而非 Next.js/Astro

- 状态：已采纳（2026-07）
- 相关：基线 §2/§12、[ADR-007](./ADR-007-仓库与演进.md)

## 背景

个人内容站 + 未来 Agent 交互。核心矛盾：想要 Vite 的纯 React 心智与开发体验，又必须满足内容站的 SEO（爬虫可读的完整 HTML）。备选：Next.js 15+（RSC/App Router）、Astro、裸 SPA。

## 决策

采用 **Vite + React Router 框架模式**，`ssr: false` + `prerender()` 构建期把每个公开路由输出为完整静态 HTML。不用裸 SPA，不用 Next.js，不用 Astro。

**落地说明**：实际安装为 **React Router v8**（`react-router@^8` / `@react-router/dev@^8`）。v8 是 v7 框架模式（React Router 与 Remix 合并形态）的延续，`react-router.config.ts` 的配置模型（`appDirectory`/`ssr`/`prerender`）与 v7 一致，本决策的全部论证不受版本号影响。

## 理由

- prerender 输出静态 HTML，SEO 能力与 SSG 框架同级——"Vite 但要 SEO"的矛盾已化解。
- 零 RSC 学习成本：Next.js 的 App Router/RSC 对第一阶段（纯内容展示）是净负担。
- Astro SEO/JS 体积最优，但 Agent 交互与全 React 生态灵活性弱，且引入第二套组件心智。
- loader/route 模型与 Next.js 概念同构，保留迁移退路。

## 后果

- 正面：纯 React 心智；路由级代码分割自动；每个公开路由是静态 HTML。
- 负面/边界：按请求动态个性化 OG 图需要运行时服务端（延后）；"登录后内容 + SEO 并存"的混合渲染暂不支持。
- prerender 路径枚举经 `scripts/content-urls.ts`（见 ADR-002 与 ARCHITECTURE.md 偏差记录③）。

## 重新评估条件

需要运行时 SSR（动态 OG、登录态 SEO）时：先评估 RR 开 SSR 模式，再评估迁 Next.js（迁移量约 1.5–2.5 周，组件/样式/令牌 100% 复用）。技术栈锁定 12 个月，触发条件不满足不重开讨论。
