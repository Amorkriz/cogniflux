# ADR-010 私密内容访问控制：nginx auth_request 复用 Workspace 登录态

- 状态：已采纳（2026-07），待实施（实施前置调研进行中）
- 相关：[ADR-001](./ADR-001-框架选型.md)、[ADR-002](./ADR-002-内容架构.md)、[ADR-003](./ADR-003-内容访问抽象.md)、nginx.conf、docs/CONTENT.md

## 背景

站点为纯静态预渲染架构（ADR-001），所有页面构建期生成 HTML。新需求：部分文章"存在性公开、正文仅作者可见"，且外部访客连真实标题都不可知。核心矛盾：静态产物天然全量公开，需在不破坏纯静态架构的前提下引入访问控制层。

## 决策

- **内容模型**：新增 `visibility: public | private` 字段（默认 `public`）。
- **访问控制**：nginx `auth_request` 复用既有 Workspace 登录态（twinspark 的 JWT 会话 Cookie）——作者登录后无感直达；未登录访问私密路径返回 401，由 nginx 引导至友好提示页。
- **口令门按路径可配置**：保护清单与"文章"不耦合，将来其他私密页面（如知识总览页）可直接纳入。
- **列表页统一中性占位**：对所有访客（含作者本人）显示中性占位卡（"私密文章 + 日期"），真实标题与摘要不进入任何公开 HTML。
- **中性 slug**：私密文章 slug 采用中性编号（如 `p-2026-001`），避免 URL 泄露主题。
- **中性 frontmatter 约定**：frontmatter 会随 eager glob 进入公开 JS chunk，故私密文章 frontmatter 不得含秘密——`title` 固定为“私密文章”、`summary` 置空或固定中性文案、禁设 `cover/seo/related`；真实标题写在正文首个 H1（随正文受保护），由 `pnpm validate-content` 强制校验。
- **私密 chunk 隔离**：私密正文原文被排除出 eager `?raw` glob（不进任何公开 chunk，代价是无 readingTime/TOC）；懒加载正文 chunk 经 Vite `chunkFileNames` 输出到 `assets/private/`，与 HTML 路径同受 nginx `auth_request` 拦截（且不给 immutable 长缓存）——只保护 HTML 路径不构成保护。
- **插图同门保护**：私密文章插图存放于 `public/images/private/{slug}/`，经 `/images/private/` 路径纳入同一口令门（nginx `auth_request` + no-store）。
- **SEO 排除**：私密文章完全排除出 sitemap 与 RSS；详情页照常 prerender（受 nginx 拦截保护）。

## 备选与否决

- **HTTP Basic Auth**：实现最简，但原生弹窗体验差、需维护独立口令；保留为降级备选。
- **前端 AES 加密（Staticrypt 式）**：保密强度最高，但需改造构建管线，复杂度与当前需求不匹配。
- **仅 `status: draft` 本地可见**：零成本但线上不可访问，且混用"未完成"与"私密"两种语义。
- **登录后列表回显真实标题**（客户端增强 + 受保护元数据清单）：体验更好但工程量大，按"两次规则"推迟；当前方案升级路径平滑。

## 后果

- 私密内容的可读性依赖后端在线；nginx 对 twinspark 为惰性解析，后端故障不影响公开内容与静态站启动。
- 纯静态架构不被破坏：私密页仍是构建期 prerender 的静态 HTML，访问控制完全落在 nginx 层。
- 新增 nginx 配置与内容 schema 的耦合点（保护路径清单 ↔ `visibility` 字段），需在部署文档中注明。

## 重新评估条件

若"登录后列表回显真实标题"的诉求第二次出现，评估客户端增强 + 受保护元数据清单方案；若 twinspark 登录态不可用或后端长期离线成为常态，评估降级到 HTTP Basic Auth 或前端加密路线。
