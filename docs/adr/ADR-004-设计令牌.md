# ADR-004 设计令牌：CSS Variables 为源 + Tailwind v4 @theme inline

- 状态：已采纳（2026-07）
- 相关：基线 §9、docs/DESIGN.md、[ADR-005](./ADR-005-组件策略.md)

## 背景

随手写的 `#3b82f6`、`137px`、`0.37s` 是换肤和一致性的天敌。需要"换一组令牌 = 换一套皮肤"，且未来即使弃用 Tailwind，令牌也要幸存。

## 决策

- 全部视觉决策落在 `src/styles/tokens.css` 的 CSS Variables，两层结构：**Primitive（原料，业务禁用）→ Semantic（业务唯一入口）**。
- Tailwind v4 CSS-first（无 tailwind.config.js），`globals.css` 用 `@theme inline` 把 Semantic 令牌映射为工具类（`bg-surface`、`text-primary`、`rounded-card`…）。
- 主题 = `[data-theme="x"]` 下的一组 Semantic 变量覆盖（`themes/light.css`、`themes/dark.css`）；dark 变体经 `@custom-variant dark ([data-theme="dark"] &)` 由 data-theme 驱动。
- 切换：localStorage（`cogniflux-theme`）+ root.tsx 内联防闪烁脚本，默认跟随系统偏好。

## 理由

- 令牌在 CSS Variables 层，与 Tailwind 解耦——工具类只是消费端。
- `inline` 使工具类直接引用 `var(--…)`，主题切换实时生效、无需重编译。
- 语义层隔离让"编辑感/品牌化皮肤"只是新增一个 CSS 文件，业务组件零改动。

## 后果

- **业务红线**：只允许语义令牌类名；禁止裸色值/像素值/Primitive 令牌直用；代码评审拦截。
- 主题必须覆盖 Semantic 层全部颜色并满足 WCAG AA（正文 4.5:1）。
- 基线的 `ThemeDefinition` TS 接口暂未落码，阶段 1 以 CSS 手工同步两主题（记录于 DESIGN.md §5）。
- 动效令牌 CSS/TS 双出口（tokens.css + shared/motion/tokens.ts），修改需两侧同步。

## 重新评估条件

主题数 ≥3 或手工同步出错 ≥2 次时，引入"从 TS 定义生成主题 CSS"的脚本；弃用 Tailwind（不预期）时令牌层原样保留。
