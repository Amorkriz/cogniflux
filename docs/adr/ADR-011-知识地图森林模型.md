# ADR-011 个人知识地图：森林 + 软链接模型而非力导向图谱

- 状态：已采纳（2026-07），数据 schema 与组件待实施
- 相关：[ADR-002](./ADR-002-内容架构.md)、[ADR-005](./ADR-005-组件策略.md)、[ADR-010](./ADR-010-私密内容访问控制.md)、docs/CONTENT.md

## 背景

作者计划对多领域（前端、金融等非计算机领域）做长期学习管理，需要个人知识地图/图谱。站点哲学为 Content as Code、克制引入依赖。核心问题：如何用最小依赖表达"领域内有序路线 + 跨域松散关联"的知识结构。

## 决策

- **数据模型 = 森林 + 软链接**：每个领域一个 TS 数据文件（`content/data/knowledge/` 下），共享 Zod schema。节点含 `id`、所属阶段、状态（未开始/进行中/已完成/搁置）、目标深度（了解/会用/精通）、验收标准、关联站内笔记（`{ kind, slug }`）、跨域软链接（`links: [nodeId]`）。
- **渲染分层**：领域内为纵向路线图组件；全局为领域卡片总览；跨域关系以节点详情中的链接列表表达。
- **不引入力导向图/图可视化库**：信息密度低、依赖重。触发条件——跨域关联规模大到链接列表形式不可用时再评估。
- **演进路径**：第一阶段 schema 落地并嵌入私密学习文章；第二阶段领域数量 ≥3 时升级独立总览页。Git 提交历史天然充当学习时间线。

## 备选与否决

- **力导向知识图谱**：视觉华丽但不可导航，违背站点克制原则。
- **外部工具（Obsidian 等）**：图谱现成，但学习记录脱离站点生态，无法与文章/项目互相引用。

## 后果

- 知识数据与站内内容同仓同管线：Zod schema 校验、Git 版本化、与文章/项目双向引用均零额外基建。
- 跨域关系表达力受限于链接列表形式，属有意取舍（见重新评估条件）。
- 待决事项：知识总览页公开或私密未定，schema 设计对两者兼容（私密路线依赖 ADR-010 的按路径保护清单）。

## 重新评估条件

跨域关联规模大到链接列表形式不可用时，评估引入图可视化；领域数量 ≥3 时启动第二阶段独立总览页。
