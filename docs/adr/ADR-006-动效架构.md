# ADR-006 动效架构：Motion primitives + 动效令牌

- 状态：已采纳（2026-07）
- 相关：基线 §11、docs/DESIGN.md §6

## 背景

动效是"可信的工程感"的一部分，但散落各处的动画参数会失控，炫技与卡顿直接摧毁定位；且必须全站尊重 `prefers-reduced-motion`。

## 决策

- 动效收敛为少量 **primitives**（`src/shared/motion/`）：`FadeIn` / `SlideUp` / `Stagger` / `PageTransition`（仅 opacity 150ms）/ `Collapse`——这是全站动效的**唯一 Motion 触点**。
- 库：Motion（framer-motion 后继）+ `LazyMotion + domAnimation + m` 组件全局包裹（`src/app/providers.tsx`），运行时 ~5KB gzip。
- 参数全部来自**动效令牌**：CSS 侧 `tokens.css`（fast 120 / base 200 / slow 320 / narrative 500ms + ease-out/emphasized），JS 侧 `shared/motion/tokens.ts` 同源同值。
- 分层：微交互（hover/focus）→ 纯 CSS transition；入场/路由过渡 → primitives；领域专属动效（AgentStatusBadge 呼吸点 `animate-breathe`）→ 领域组件内实现但消费令牌。

## 理由

- 收敛为 primitives：动效语言一致、reduced-motion 只需在一处保证、替换动效库只改 primitives 层。
- 组件只接受 `state` props（CSS `data-state` 或 primitives 响应），业务代码不直接操纵动画参数——动效与业务解耦。

## 后果

- 性能红线：只动 `transform/opacity`；stagger 上限 12 项（`STAGGER_LIMIT`）；滚动触发一次性（`whileInView`），禁滚动绑定连续动画。
- reduced-motion 双保险：primitives 内置 `useReducedMotion`（时长归零、位移取消）+ CSS 层 `motion-reduce:animate-none` / `@media (prefers-reduced-motion)`。
- 不做清单：粒子、鼠标跟随、视差长卷轴、3D 翻转、打字机循环、首屏大型序列动画。
- 双出口令牌需人工同步（修改任一侧必须同步另一侧）。

## 重新评估条件

滚动叙事/CommandPalette 动效等新需求以新增 primitive 落地，不绕过本层；若 Motion 运行时预算被突破（首页 JS >180KB gzip），评估降级为 CSS-only。
